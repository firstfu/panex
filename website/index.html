The terminal that tells you which agent needs you

Twenty minutes ago Claude Code hit a permission prompt, and you were in another window. panex is a terminal that lights up the agent waiting for you, so you can run several at once, and it brings everything back if the app closes or crashes.

Features

Built around how agents actually work

Every feature answers one question: what is each agent doing right now, and what do I need to do next?

Know which agent needs you

When Claude Code asks for permission or finishes, its tab gets a dot and its workspace lights up in the sidebar with the message. Blue means it is waiting for you, green means it is done.

  • While working, the workspace shows a spinner and how long the turn has run
  • In the background you also get a desktop notification and a taskbar flash
  • Ctrl+Shift+U jumps to the tab that needs you
  • Set up automatically through Claude Code hooks; nothing to turn on

Crew mode: let an agent start other agents

Ask Claude Code in a panex tab to split a job across parallel agents. It opens new workspaces right below its own, each in its own git worktree if you like, and you can watch and type into every one.

  • It waits for them, and tells you when one is asking a question instead of answering for you
  • When they finish it collects their work from git
  • Only processes started inside panex can send these commands
Crew mode in detail →
# inside a Claude Code tab 
$ panex-cli open --worktree try-a -- claude "approach A"
$ panex-cli open --worktree try-b -- claude "approach B"
$ panex-cli wait
try-a  done
try-b  needs input

Comes back after a crash

Workspaces, tabs, each tab's shell and folder, and the scrollback are saved as you go. Close panex, reboot, or kill it: next time it opens exactly where you were.

  • panex remembers which Claude Code session each tab was running and runs claude --resume for you when you open it
  • Tabs where you had already quit Claude stay at the prompt
  • Restored tabs don't start a shell until you open them

See what changed without leaving the terminal

A read-only Git panel lists staged, changed and untracked files and the last 30 commits. Click one to read its diff over the terminal. The Files tab shows the whole project as a tree, with Markdown rendered and code highlighted.

  • Sidebar badges: ↑ unpushed, ↓ behind, ● uncommitted
  • No polling, no file watcher: it reads once after a prompt, a finished turn, or when you return
  • Raw HTML in documents is shown as text, so a file can't run anything

A worktree for every task

Right-click a workspace to start a new one in a fresh git worktree, with your .env files copied over and an optional setup command. Worktrees of one repo are grouped in the sidebar.

  • Closing one lists what would be lost first: uncommitted files, commits on no other branch, agents still working
  • Works with Claude Code's own --worktree and EnterWorktree

The details that make a terminal comfortable

⌨️

Every shortcut is yours

Click a shortcut in Settings and press new keys. Chords, two bindings per action, or unbind a key so it reaches the terminal.

🔐

SSH connections

Pick a host from ~/.ssh/config or type user@host:port. It runs your system's ssh; passwords are never stored.

🎨

Look the way you like

Transparency, Mica or Acrylic on Windows 11, any installed monospace font, color emoji, and an English or Traditional Chinese interface.

🔎

Search and links

Ctrl+Shift+F searches scrollback. Ctrl+click opens URLs, or src/main.ts:120 in VS Code or Cursor at that line.

🧾

One JSON config

Plain file with a schema for editor completion, applied about 0.3 s after you save. The Settings panel writes to the same file.

🛡️

Asks before interrupting

Closing panex, a tab or a workspace while an agent is mid-task asks first, so a stray click doesn't cut it off.

Measured on the Windows release build. panex never runs a timer while idle.

Most of the memory in Task Manager belongs to WebView2, which draws the window. Restored tabs don't start a shell until opened, and only the visible tab uses GPU rendering.

Privacy

No telemetry. Everything is in the repo.

One network call

The update check asks GitHub for latest.json. Turn it off in Settings and panex makes no connections at all.

Verified updates

Updates are never installed on their own, and each download is checked against a public key built into the app.

One file outside its folders

~/.claude/settings.json gets the hooks, after a backup, keeping your other hooks. See hooks.rs.

Install

Download panex

The installer isn't code-signed and the Mac app isn't notarized, so Windows and macOS warn once on first run. The steps below get past it.

  1. Download panex_0.7.11_x64-setup.exe from Releases.
  2. Run it. SmartScreen warns the first time: click More info, then Run anyway.
  3. panex installs for your user only (no administrator rights) and adds a Start menu entry.

Needs Windows 10 or 11 with WebView2, already part of Windows 11 and up-to-date Windows 10.

Download for Windows
  1. Download panex_0.7.11_aarch64.dmg from Releases, open it and drag panex into Applications.
  2. Open it once. macOS blocks the first launch: go to System Settings → Privacy & Security and click Open Anyway.
  3. If macOS says the app is damaged, run this and open it again:
    xattr -cr /Applications/panex.app

Apple Silicon only. ⌘ replaces Ctrl in the default shortcuts.

Download for macOS

After that, updates arrive in the app: a line appears at the bottom of the sidebar, and Update and restart does the rest. Or build from source.

FAQ

Common questions

How do I run multiple Claude Code sessions at once?

Press Ctrl+N for a workspace per project or task and start claude in each. The sidebar shows which one is working, waiting for you or done, and Ctrl+Shift+U jumps to the one that needs you. When several sessions work on the same repo, give each its own git worktree (right-click a workspace) so they don't edit the same files.

Is panex a terminal for Claude Code on Windows?

Yes. It is built for Windows 10 and 11 first (cmd, Windows PowerShell and PowerShell 7) and also runs on macOS with Apple Silicon. Status lighting, resume and crew mode use Claude Code's hooks, which panex installs by itself.

Does it only work with Claude Code?

Any program runs in a panex tab, since it is a normal terminal. Status lighting and crew mode rely on Claude Code's hooks. Other tools can still notify by running panex-cli notify "message" or printing a bell, OSC 9 or OSC 777 sequence.

Notifications don't show up

panex sets hooks up itself at launch. If the bottom of the sidebar says notifications are not enabled, it couldn't write ~/.claude/settings.json (for example the file isn't valid JSON): fix it and click Enable. Only sessions started inside panex light up tabs.

Ctrl+T or Ctrl+N doesn't reach my program

panex handles its shortcuts first. Claude Code uses Ctrl+T for its todo list, for example. Open Settings → Shortcuts and rebind or clear the panex shortcut.

Do I lose macOS permissions when I update?

No. Releases are signed with the same certificate every time and macOS ties permissions to that signature. A build you compile yourself is signed ad hoc, so macOS asks again after each rebuild.

Where is my data?

Settings: ~/.config/panex/panex.json (%USERPROFILE%\.config\panex\ on Windows). Layout and scrollback: %APPDATA%\dev.panex.terminal\ on Windows. Delete either to start fresh.

How do I uninstall it?

Use Settings → Apps → Installed apps → panex → Uninstall on Windows. To remove your data, delete the two folders above, then remove the panex-cli entries from ~/.claude/settings.json or restore settings.json.panex-bak.

Are split panes coming?

Not yet. Split panes and listening ports in the sidebar are only built once real people ask for them: open an issue and tell the author how you'd use it.
