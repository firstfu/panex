Guide

Everything panex does, in the order you'll meet it. On a Mac, read Ctrl as ⌘ and Alt as ⌥ (this page switches the key caps for you).

Workspaces and tabs

panex has two levels. The sidebar lists workspaces, one per project or task. Each workspace has its own row of tabs along the top, and each tab is one shell.

  1. Press Ctrl+N for a new workspace and Ctrl+T for a new tab in the current one. A new tab opens in the same folder as the tab you were in.
  2. Rename with Ctrl+Shift+R (workspace) or Ctrl+Alt+R (tab), or double-click the name. Right-click a workspace to give it a color.
  3. Drag a workspace or tab to reorder it. Ctrl+1…9 jumps to a workspace and Alt+1…9 to a tab (9 is always the last).
  4. Each sidebar row shows the folder, the git branch and its status. Closing the last tab closes the workspace; closing the last workspace opens a fresh one.

Choosing a shell

On Windows the default is cmd, with Windows PowerShell and PowerShell 7 available when installed: pick one under Settings → Terminal → Default shell, or from the ⌄ menu next to New workspace. On macOS tabs start your login shell ($SHELL).

Agent notifications

This is what panex is for: knowing which of several agents is waiting for you.

StateWhat you see
WorkingA spinner and the elapsed time of the current turn on the workspace.
Needs youA blue dot on the tab and the agent's message in the sidebar (a permission prompt or a question).
DoneA green check and how long the turn took.

A workspace with several tabs shows the most urgent status among them. If panex is in the background you also get a desktop notification and a taskbar flash; the tab and workspace light up either way. Ctrl+Shift+U jumps to the tab that needs you.

How it is wired

At startup panex adds Notification, Stop, StopFailure, UserPromptSubmit and SessionEnd hooks to ~/.claude/settings.json. Each runs panex-cli notify, which passes the message to panex. The file is backed up first (settings.json.panex-bak) and your other hooks are kept. Outside panex the helper exits at once, so Claude Code in other terminals is unaffected.

Other tools

panex-cli notify "build finished"

or print a bell (\a), an OSC 9 or an OSC 777 sequence from any program.

Not lighting up? Notifications only reach sessions started inside panex. If the bottom of the sidebar says notifications are not enabled, panex couldn't write the settings file (is it valid JSON?). Fix it and click Enable.

Crew mode

Crew mode lets one agent start others in new panex tabs, wait for them, and gather the results. You don't type any commands: ask Claude Code, in a panex tab, something like “try three approaches to this in parallel”.

  1. Claude opens a new workspace for each helper, right below its own. With worktrees on, each helper gets its own git worktree so they don't overwrite each other.
  2. The helpers run in tabs you can open, watch and type into. Opening them is silent: your view doesn't switch.
  3. Claude waits for them. If one stops to ask something, Claude tells you rather than answering for you.
  4. When they finish, Claude collects the work from git.

The two commands behind it

# start a command in a new workspace (optionally in a new worktree)
panex-cli open --worktree try-a -- claude "approach A"

# block until those agents finish or need you
panex-cli wait

panex-cli help has the full details. panex installs a small Claude Code skill (~/.claude/skills/panex/SKILL.md) that teaches Claude to use them; it does nothing outside panex.

Safe by design. Requests must carry a token that panex generates at every launch and hands only to shells it started. Anything outside panex is refused. wait costs nothing while waiting, and it relies on Claude Code's hooks, so it works for Claude Code only.

Restore and resume

Close panex, reboot, or kill it from Task Manager: it reopens where you were.

Comes backDoes not
Workspaces, tabs, colors, order, groupsPrograms that were running (a dev server, a build)
Each tab's shell and working directoryAnything in the alternate screen (full-screen programs)
Scrollback text (last 1000 lines)The last few seconds before a crash (saved every ~4 s)
The Claude Code session of each tab that was still running one

For Claude Code, panex remembers each running session's id. When you open that tab after a restart it runs claude --resume <id> for you and you land back in the conversation. Tabs where you had already quit Claude stay at the prompt. Turn it off in Settings → Terminal.

Restored tabs don't start their shell until you open them, so a restart doesn't launch every shell at once.

Git and Files panels

A panel on the right, shared by two tabs. It is read-only: it never stages, commits, pushes or fetches.

Git — Ctrl+Shift+G

  1. Lists staged changes, changes and untracked files for the current tab's repo, plus the last 30 commits with unpushed ones marked.
  2. Click a file or a commit to read its diff over the terminal. Esc closes it.
  3. In the sidebar, each branch carries ↑ unpushed commits, ↓ commits waiting upstream (as of your last fetch) and ● uncommitted changes. You can see at a glance which agent left work behind.

Files — Ctrl+Shift+E

  1. Shows the whole project as a folder tree, the way git sees it: tracked and new files, minus what .gitignore excludes. Outside a repo it scans the folder instead (hidden folders, node_modules and target skipped).
  2. Changed files carry the same letters as the Git tab, and folders with changes inside get a dot, so you see which part of the project an agent touched before opening anything.
  3. Click a file to read it: Markdown rendered, code highlighted with line numbers (over 300 KB it isn't colored), images and SVG shown. Other files, such as PDFs and spreadsheets, get Quick Look (macOS), Open with default app and Show in Finder / Explorer.
Costs nothing when unused. No polling and no file watcher. panex runs git status once after a shell prompt, after Claude Code finishes a turn, or when you return to the window, and only for the tab you're looking at. Git also runs with --no-optional-locks so it never fights an agent for the index lock.
Files can't run anything. Raw HTML in a document is shown as text, images in Markdown aren't loaded, and links open in your browser. Reading is limited to the project: .. and symlinks pointing outside are refused.

Worktrees and groups

A git worktree is a second checkout of the same repo in another folder, so an agent can work on a branch without disturbing yours.

Start one

  1. Right-click a workspace → New workspace in a new worktree… (or bind newWorktree).
  2. Type a branch name; both the branch and start-point fields offer your local branches. An existing branch is checked out as is; otherwise it's created from the start point.
  3. panex creates the worktree next to the repo (<repo>-worktrees/<branch>), copies the files listed in worktree.copyFiles (default .env and .env.local, never overwriting), opens a workspace named after the branch and runs worktree.setupCommand if you set one.

Files git doesn't track, like .env and node_modules, don't appear in a new worktree by themselves, which is why those two settings exist.

Remove one

Right-click its workspace → Close workspace and delete worktree…. Before deleting, panex lists what you'd lose: uncommitted files, commits that no other branch or remote has, and agents still working. If any exist the button reads Delete anyway and focus stays on Cancel. You choose whether to delete the branch too; with unique commits it is kept by default. The main checkout can never be deleted this way.

Worktrees removed some other way (git worktree remove, rm -rf) drop out of the sidebar by themselves the next time panex gets focus or a shell returns to its prompt.

Groups

A repo's checkouts are grouped: the main folder's workspace on top with a fold arrow, its worktrees indented below and tagged worktree. Folded, the top row shows the most urgent status inside. Right-click to add a workspace to a group, move it out, fold, or dissolve a group. A group always has at least two members, and its members stay adjacent so Ctrl+number still matches the top-to-bottom order.

With Claude Code's own worktrees

When Claude Code opens a worktree (claude --worktree, EnterWorktree), panex creates it next to the repo and adds a workspace for it under the repo. The conversation stays in the tab where you started it. When Claude removes it, panex deletes it and closes that workspace. Turn this off in Settings → Terminal. Because the hooks are global, Claude Code outside panex behaves as it normally does.

SSH connections

  1. Open the ⌄ menu next to New workspace → SSH connection….
  2. Pick a host from your ~/.ssh/config (it follows Include and skips wildcards) or type [user@]host[:port].
  3. It opens in its own workspace; new tabs there connect to the same host.

panex runs your system's ssh, so keys, config, known_hosts and your agent work as usual. Passwords are typed in the terminal and never stored. If the link drops it says so; press Enter to reconnect, and reopening panex reconnects automatically. SSH tabs don't remember a folder, since a remote path means nothing locally.

Shortcuts

Open Settings → Shortcuts, click a shortcut and press the new keys. Bind two combinations to one action, use chords such as Ctrl+K Ctrl+N, or unbind a key so it reaches the terminal. A combination can have one owner: the previous one loses it, and you're told which.

Configuration

The Settings panel (⚙ or Ctrl+,) has General, Appearance, Terminal, Shortcuts and Config file pages. It writes to one plain JSON file, ~/.config/panex/panex.json (%USERPROFILE%\.config\panex\panex.json on Windows), which you can also edit by hand.

  • Write only the keys you want to change; everything else uses defaults.
  • panex.schema.json sits next to it, so editors like VS Code offer completion and descriptions.
  • Saving applies about 0.3 s later. If the file doesn't parse, panex keeps the last good settings and shows the error with a button to open the file.
  • If the panel covers something you want to read, drag it by its side rail.
{
  "$schema": "./panex.schema.json",
  "schemaVersion": 2,
  "app": { "opacity": 85, "windowEffect": "acrylic" },
  "terminal": { "fontSize": 15, "defaultShell": "powershell" },
  "shortcuts": {
    "bindings": {
      "newTab": [["ctrl+t"], ["ctrl+shift+t"]],
      "renameTab": "f2",
      "nextWorkspace": ["ctrl+k", "ctrl+n"],
      "clearScrollback": null
    }
  }
}

In bindings: a string is one combination, an array of strings is a chord, an array of arrays lists alternatives, and null unbinds the action. The schema lists every action id.

Terminal tips

  • Search: Ctrl+Shift+F searches the scrollback.
  • Links: Ctrl+click a URL to open it in your browser, or a path like src/main.ts:120 to open the file, in VS Code or Cursor at that line if you choose one in Settings → Terminal.
  • Copy and paste: Ctrl+C copies when text is selected and interrupts otherwise; Ctrl+V pastes. Dragging files in pastes their paths (quoted if they contain spaces).
  • Fonts: pick any installed monospace font; Chinese and emoji fall back automatically, and emoji are in color.
  • Window: adjustable opacity (text stays sharp, only the background fades), plus Mica or Acrylic backgrounds on Windows 11.
  • Interface language: English or Traditional Chinese, following your system or set in Settings.
  • Safe close: closing panex, a tab or a workspace while an agent is mid-task asks first (Settings → Terminal).
  • Dim and italic text: Claude Code's dim hints are drawn in a fixed gray and italics are upright. This is on purpose: with the GPU renderer they otherwise got a black box behind them.

macOS permissions

panex needs none itself, but programs in your tabs count as panex to macOS. When an agent sends keys with osascript or takes a screenshot with screencapture, it's panex that needs Accessibility or Screen Recording.

Settings → General → Permissions shows which are allowed and opens the right System Settings page. It reads the state only when you open the page or return to the window, never in the background. Releases are signed with one certificate, so granted permissions survive updates.

Updating

When a newer version is out, a line appears at the bottom of the sidebar. Click Update and restart: panex downloads, verifies and installs it, then restarts. Restarting ends programs in your tabs (an agent mid-turn gets a confirmation first); workspaces, scrollback and Claude Code conversations come back. Check by hand in Settings → General, or turn the automatic check off there.

Still stuck? Open an issue with your OS version and the shell you were using.
