# 系統架構大圖

> **何時讀**：每個 session 開場必讀。

panex：開源、跨平台（Windows 優先）的多 agent 終端機 App，模仿 cmux（manaflow-ai/cmux，macOS only）的核心體驗。技術棧 Tauri 2（Rust）+ xterm.js 6 + portable-pty，前端 TypeScript + Vite（目前沒有 UI 框架；2026-10-24 起允許引入，見 `boundaries.md`）。授權 MIT；cmux 是 GPL，只參考功能、不抄程式碼。

## 需求（使用者定案）

- 跟 cmux 一樣的兩層結構：側欄是「工作區」（Ctrl+N），每個工作區上方一排水平「分頁」（Ctrl+T），每個分頁一個終端機。
- 預設 shell 為 cmd，可選 Windows PowerShell／PowerShell 7（偵測得到才列）。
- agent 通知：Claude Code hooks → `panex-cli notify` → 分頁亮起、所屬工作區顯示其分頁中最緊急的狀態；視窗不在前景時再加 toast＋工作列閃爍。
- 關閉或 crash 後重開，還原工作區、分頁、各分頁 shell 與 cwd、捲動歷史（跟 cmux 一樣；執行中的程式不保留）。
- 效能與資源占用最小化。

## 專案狀態

- 已公開發佈：https://github.com/firstfu/panex（public、MIT），最新 release v0.2.0 附 NSIS 安裝檔（v0.1.0 為首發）。
- README 仿使用者另一個專案 Liftoff 的寫法（置中頂部、Why／Features／Performance／Privacy／FAQ…），英文版在根目錄、繁中版在 `translations/README.zh-Hant.md`，截圖在 `assets/`。
- 介面有英文與繁體中文（`app.language`：`auto` 依 webview 的 `navigator.language`，`zh*` 用繁中、其餘用英文）。發布與重拍截圖的做法見 `operations.md`。

## 模組地圖

| 位置 | 職責 |
|---|---|
| `src-tauri/src/pty.rs` | 每分頁一個 PTY。輸出走 Tauri `Channel` 的 raw bytes（不經 JSON、不在 Rust 解 UTF-8）；waiter 執行緒等子程序結束後才丟掉 master（ConPTY reader 不會自己 EOF）。channel 可替換，webview reload 後重接仍在跑的 shell。Windows 上每個分頁的 shell 放進自己的 Job Object（`job.rs`，`KILL_ON_JOB_CLOSE`）：關分頁、shell 結束、panex 結束或當掉，都會把這個分頁開出的整棵程序收掉，**包含從分頁 `start` 出去的 GUI 程式**（`code .`、`start notepad`）；原因是 Claude Code 在 Windows 收不乾淨有自己 console 的 MCP server。同一個 job 也供 `pty_usage` 查分頁的記憶體與程序數（分頁總覽面板 `src/usage.ts`，原名「資源使用」：依狀態分組列出所有分頁〔在等你／正在做／做完／閒著／睡著了／未啟動，`remote.ts::groupOf`〕，含最後訊息、這一輪時間、記憶體，每列可叫醒、休眠、設不休眠；只在打開、重新整理、按按鈕後讀一次，不輪詢），以及分頁列每個分頁、側欄每個工作區旁的記憶體數字（`src/mem.ts`：只在切換分頁、視窗取回焦點、agent 開始或結束一輪、休眠／叫醒／shell 結束、滑鼠移到分頁或工作區上時讀，300 ms 內的多個事件併成一次；設定 `app.liveMemory`（預設關）打開時，視窗在前景才每 10 秒多讀一次），並供 `pty_hibernate`（分頁休眠）判斷與結束。macOS 對應的是 `job_unix.rs`（同一個 `Job` 介面）：以 `ps` 取全機程序表，從 shell pid 沿 ppid 往下找整棵子孫樹，逐一 SIGKILL（不殺 process group：zsh 把每個指令放進各自的 group）；記憶體是 RSS（含共用頁，比 Windows 的 private 偏高）；**沒有 kill-on-close，panex 當掉時分頁程式會殘留**。休眠的「只剩 claude」判斷規則共用 `agent_rule.rs`（兩平台只差執行檔名）。 |
| `src-tauri/src/session.rs` | `app_data_dir`（`%APPDATA%\dev.panex.terminal\`）下的 `session.json`：`{workspaces:[{id,title,color,tabs:[{id,shell,cwd,title}],active}], active}`，與 `scrollback/<分頁 id>.txt`。前端擁有版面、整份 `session_save`；全部 tmp + rename 原子寫入；檔案壞了就當空白開始。讀到 v0.1 的扁平 `{tabs,active}` 會先備份 `session.v1.json.bak` 再轉成「每分頁一個工作區」（工作區 id ＝ `w`＋分頁 id 前 11 碼）。 |
| `src-tauri/src/notify.rs` | named pipe `\\.\pipe\panex-<USERNAME>`（Unix 為 socket）收 `panex-cli` 的 JSON，轉成 `agent-notify` 事件；`alert` 指令發 toast＋閃工作列。每則訊息是一行 JSON：沒有 `op` 的是 hook 通知（`notify` 不帶換行就關閉連線，同樣讀得到）；有 `op` 的是控制請求，交給 `control.rs`，答覆寫回同一條連線。 |
| `src-tauri/src/control.rs` + `src/control.ts` | 讓 agent 驅動 panex：`panex-cli open`／`wait`。請求必須帶 `PANEX_TOKEN`（每次啟動隨機產生，只注入 panex 自己開的 shell），外面的程序一律拒絕。`open` 由後端發 `ctl-request` 給前端（版面歸前端管）：前端用 `git_worktree_add` 開 worktree、在呼叫者的工作區下方插入新工作區、**立刻 `spawn` 但不切過去**，再用 `ctl_reply` 回傳分頁 id，60 秒沒回就逾時。`wait` 由後端直接回答：hook 訊息經過管道時順便記下各分頁的 agent 狀態（`record`；shell 結束時 `pty.rs` 呼叫 `pane_exited`），用 `tokio::sync::Notify` 等到這些分頁都不在 starting／running，或逾時（預設 110 秒，低於 agent shell 工具的 2 分鐘預設上限；最長 3600 秒）。等待期間不耗資源。狀態來自 Claude Code hooks，所以 `wait` 只對 Claude Code 有效。hooks 不會回報兩件事：使用者在權限確認或提問按 Enter 回答後 agent 繼續工作，以及按 Esc／Ctrl+C 中斷這一輪。這兩件事由前端從按鍵判斷（`agent.ts` 的 `agentKey`，靠 `tab.asking` 旗標而不是畫面上的徽章，因為正在看的分頁不會亮徽章，切過去也會清掉），再用 `agent_state` 告訴後端；沒有這一步，主 agent 在使用者核准後呼叫 `wait`，會一直拿到過時的 needs-input。用法說明只放在 `panex-cli help`，`skills/panex/SKILL.md` 只叫 agent 去讀它，免得文件跟版本脫節。**`list`／`wake`／`send`**（給「從手機連進一個控制分頁、由它操作其他分頁」用）同樣交給前端：`list` 依側欄順序列出分頁、shell 狀態（running／asleep／stopped）與 Claude 狀態；`wake` 對分頁 `spawn` 但不切過去（休眠的分頁因此 `claude --resume`）；`send` 把文字打進分頁裡的 Claude Code 並按 Enter，分頁休眠時先叫醒，等輸出安靜 2 秒（至少 4 秒、上限 45 秒，在後端 60 秒逾時之內）才送。目標可寫分頁 id 或名稱（`src/remote.ts::matchTargets`：id 優先，再比工作區／分頁標題／資料夾名，完全相等優先於包含）。`send` 的防線：分頁裡沒有 Claude 就拒絕（絕不打進純 shell，否則等於讓任何分頁的 agent 在別的 shell 執行指令）、Claude 正在問使用者時拒絕、不能送給自己、比對到多個分頁時要求改用 id；文字先過 `cleanText` 去掉 ESC 等控制字元（只留換行與 tab），用 bracketed paste 送入，150 ms 後才另送 `\r`（同一筆送出會被 Claude Code 當成貼上內容裡的換行）；按 Enter 之前先 `agent_state running`，否則緊接著的 `wait` 會拿到上一輪的 done。分頁右鍵「不要休眠這個分頁」設 `tab.noSleep`（`session.json` 的 `noSleep`，可省略欄位），擋在 `canHibernate`，手動與自動休眠都跳過它。 |
| `src-tauri/src/hooks.rs` | 把 hooks 合併進 `~/.claude/settings.json`（exec form，先備份 `.panex-bak`，只替換含 `panex-cli` 的條目）。正式安裝的 panex 在 `setup` 時呼叫 `ensure`：缺少或指向別的 panex-cli 就自動寫入，不詢問；debug／測試實例不寫。側欄「啟用」按鈕只在自動寫入失敗時出現。`agent.worktreeViaPanex` 開著（預設）時另加 `WorktreeCreate`／`WorktreeRemove` 兩個 hook（`panex-cli worktree-create`／`worktree-remove`），**一律成對進出**；使用者自己有任一個 worktree hook 就兩個都不加。原因：有了 `WorktreeCreate` hook 卻沒有 `WorktreeRemove` 時，Claude Code 會自己用 `git worktree remove --force` 刪掉，panex 收不到任何通知，側欄留下指向已刪資料夾的工作區（2026-10-22 使用者回報）。`worktree-create` 讓 panex 建 worktree，並在 repo 群組底下開一個 shell 在 worktree 裡的新工作區（會跑 setupCommand、不切畫面）；**Claude 的分頁不搬**：對話屬於原本的工作區，worktree 是另一個資料夾（2026-10-23 使用者定案，v0.5.x 曾把分頁搬進 worktree 工作區，使用者覺得很怪）。有 `WorktreeRemove` hook 時 Claude Code 自己不刪，`worktree-remove` 先通知 panex（關掉開在資料夾裡且沒在工作的分頁，也就是建立時開的那個工作區；Claude 的分頁本身在資料夾裡時才搬回主工作區，shell 還在已刪資料夾裡的話下一個提示字元 cd 回主 checkout），再自己 `git worktree remove --force`；分支照 Claude Code 的做法保留。同一個開關還裝一個 `PreToolUse` hook（matcher `EnterWorktree`，`panex-cli worktree-guard`）：在 panex 分頁裡攔下 Claude Code 內建的原地切換並 deny，理由叫它改用 `panex-cli open --worktree <分支> -- claude "<任務>"` 把任務交給新 agent。原因：`EnterWorktree` 讓同一個 session 的 cwd 切進 worktree、對話卻仍掛在原工作區，panex 另開的 worktree 工作區反而是空 shell；靠 skill 猜使用者措辭不可靠，所以攔動作。放行：不在 panex 內（hook 是全域的）、cwd 已在 linked worktree（交棒出去的 agent 不能再被轉一次）、子 agent。`ensure` 也會把 panex skill 寫到 `~/.claude/skills/panex/SKILL.md`（見 `boundaries.md`）。 |
| `src-tauri/src/bin/panex-cli.rs` | 獨立 console 小程式。`notify`：讀 hook stdin JSON，帶上 `PANEX_PANE_ID` 寫入 `PANEX_PIPE`。環境變數不在就立刻 exit 0；永遠 exit 0。`PANEX_DEBUG=1` 印出送出的內容。`open`／`wait`／`help` 見 `control.rs` 那列：在 stdout 印一行 JSON，錯誤 exit 1、`wait` 逾時 exit 2；`open` 的 `--` 之後的參數若含空白或引號就包上雙引號，接起來送進分頁的 shell。 |
| `src/*.ts`（前端） | 依功能分檔，每個檔頭有一段說明。`main.ts` 只做啟動與接後端事件（焦點、關窗、pty 結束、agent hook、設定重載）；`state.ts` 放共用狀態，其他模組會重新賦值的值（目前分頁／工作區、設定、快捷鍵、焦點、shell 清單、改名中）集中在物件 `S` 上，因為 ES module 不能從外部改別的模組的 `let`；只有單一模組用的狀態留在該模組，需要時給 getter（`isGitOpen`、`isCapturing`）。`terminal.ts`＝xterm、pty、OSC 解析（9;9 / 7 = cwd；9 / 777 / BEL = 通知）、scrollback 快照；`agent.ts`＝執行中／需回應／完成與自動接回；`workspaces.ts`＝顯示、新增、關閉（關掉工作區最後一個分頁會連工作區一起關，最後一個工作區關掉會自動開新的）、排序；`render.ts`＝側欄與分頁列；`input.ts`＝鍵盤、滑鼠、拖曳；`settings-panel.ts`、`git-panel.ts`、`search.ts`、`links.ts`、各對話框各一檔；`settings.ts`、`types.ts`、`util.ts` 沒有副作用。**頂層程式碼只查 DOM、掛事件**，不要在模組頂層呼叫別的模組的函式或讀它的常數：模組之間有循環 import，頂層讀到還沒載入完的模組會在執行期出錯（`tsc` 抓不到）。 |
| `src-tauri/src/config.rs` + `schemas/panex.schema.json` | 使用者設定檔 `~/.config/panex/panex.json`（仿 cmux 的 `cmux.json`）：只寫改過的鍵、旁邊放 schema 供編輯器補完、`notify` 監看目錄、最後一次寫入後 300 ms 發 `config-changed`。`config_set` 只改單一鍵、檔案壞掉時拒寫。目前 `schemaVersion` 2；讀到 1 時先備份 `panex.json.v1.bak` 再依 `V1_RENAMES` 改名快捷鍵 id（v1 的「分頁」＝現在的工作區）。 |
| `src/i18n.ts` | 介面語言。以繁中原文當 key、`t("原文", {var})` 查英文（找不到就回原文）；靜態 HTML 用 `data-i18n`／`-title`／`-aria`／`-ph` 標記，`translateDom()` 首次記下原文後可來回切換。新增任何使用者看得到的字串都要同時加進 `EN` 字典；`keys.ts` 的動作 label 維持繁中，顯示時才 `t()`。Rust 端錯誤訊息一律英文。 |
| `src-tauri/src/git.rs` | `git_branch(cwd)`：往上找 `.git`（目錄或 worktree 的 `gitdir:` 檔）直接讀 `HEAD`，不開 git 程序；detached 回 7 碼 hash。前端在每次 cwd 回報（每個 prompt）重查，同分頁 1 秒內不重複，所以原地 `git checkout` 下個 prompt 就更新。 |
| `src-tauri/src/ssh.rs` + SSH 連線 | ⌄ 選單「SSH 連線…」（或可綁定的 `newSsh`）開對話框，主機清單來自 `~/.ssh/config` 的 `Host`（`ssh_hosts`，跟著 `Include` 讀，略過萬用字元），也可手打 `[帳號@]主機[:埠號]`；每個連線開一個新工作區，該工作區按＋開的新分頁連同一台主機。分頁直接跑系統的 `ssh`（`pty.rs` 遇到 shell `"ssh"` 改用 `ssh::command`，尾端 `:埠號` 轉成 `-p`、主機前加 `--`），金鑰、config、known_hosts、agent 照常沿用，panex 不碰密碼。主機字串會進 ssh 的命令列，前後端都用同一套規則檢查（`valid_target`／`validSshTarget`：不得以 `-` 開頭、只收主機／帳號／埠號會用到的字元）。`session.json` 的分頁多一個可省略的 `ssh` 欄位（不需遷移）；SSH 分頁不記 cwd（遠端路徑對本機沒意義，git 分支、Git 面板、新分頁的資料夾都不用它）。斷線顯示「連線已中斷，按 Enter 重新連線」，重開 panex 會自動重連。 |
| Git 面板（唯讀） | 右側面板（`Ctrl+Alt+G`（macOS `⌘⌥G`）／上方列右側按鈕，開關與寬度存 localStorage）列出目前分頁 repo 的已暫存／變更／未追蹤檔案與最近 30 筆提交，點檔案或提交就在終端機區上方蓋一層 diff 檢視（Esc 關閉）；側欄分支後面加 `↑未推送 ↓落後 ●未提交` 徽章。後端 `git.rs` 的 `git_status`／`git_diff`／`git_log`／`git_show`：async + `spawn_blocking`、一律加 `--no-optional-locks`（不搶 agent 的 index.lock）與 `-c core.safecrlf=false`，輸出有上限（狀態 4 MB、diff 1 MB、檔案 500 筆），超過就 kill git。**沒有輪詢也沒有 watcher**：只在 prompt、Claude Code `Stop`、視窗取得焦點、面板開啟／切分頁時讀一次（300 ms 防抖，同分頁同時只跑一個），而且只讀各工作區目前顯示的分頁（其他標 `gitStale`，切過去才讀）；提交列表只在面板開著且 HEAD 或未推送數變了才重讀。↓ 是上次 fetch 的結果，panex 不會自己 fetch。不做 stage／commit／push。 |
| 檔案分頁（唯讀，`src/files-panel.ts`＋`src-tauri/src/files.rs`） | 右側面板分成「Git｜檔案」兩個分頁（`Ctrl+Alt+E`（macOS `⌘⌥E`）／`toggleFilesPanel`，最後選的分頁存 localStorage `panex.panelTab`），兩者共用終端機上方的檢視層。檔案分頁用資料夾樹列出目前分頁的整個專案：repo 根目錄用 `git ls-files --cached --others --exclude-standard`（照 `.gitignore`，再濾掉已刪除但未暫存的檔），不在 git 裡就掃資料夾（略過隱藏與 `node_modules`／`target` 等，深度 8）；上限 20000 個檔。檔案標 Git 分頁同一套字母、內含變更的資料夾加點（`src/tree.ts` 純函式，有單元測試）；展開狀態依 repo 存 localStorage `panex.treeOpen`。點檔案：Markdown 用 `markdown-it` 排版，其他用 `highlight.js`（common 語言，超過 300 KB 不上色）加行號，兩個套件都是第一次打開檔案才 dynamic import。圖片（png／jpg／gif／webp／avif／bmp／ico／svg）由 `file_image` 讀成 `data:` URL 用 `<img>` 顯示（CSP 本來就允許 `data:` 圖片；SVG 放在 `<img>` 裡 script 不會執行，另有「看原始碼」），超過 20 MB 不內嵌。其他二進位（PDF、Office、音訊、影片…）不在 panel 內渲染（pdf.js 太大且要放寬 worker CSP、SheetJS 的 npm 版已停更），改顯示類型＋大小＋`file_action` 三個按鈕：macOS 的 Quick Look（`qlmanage -p`）、預設 App 開啟、在 Finder／檔案總管顯示。**安全**：這個頁面能呼叫 `pty_write`，所以 `markdown-it` 設 `html: false`（文件裡的 HTML 只當文字）、圖片換成替代文字（也因 CSP 本來就載不到）、標題 id 一律加 `md-` 前綴（避免撞到 App 自己的元素 id）、連結一律攔下：http(s) 交給系統瀏覽器，相對路徑在樹裡開啟。`file_read` 先 canonicalize 再比對前綴，`..` 與指向外面的 symlink 都拒絕，上限 1 MB。跟 Git 分頁一樣沒有 watcher：只在開分頁、切分頁、git 狀態重讀（prompt、Stop、焦點）時重讀樹。不做編輯、新增、改名、搜尋（2026-10-24 使用者定案：Git 已經看得到最近改了什麼，這裡要的是整個專案的結構）。 |

## 還原機制

- cwd 來源：cmd 啟動時設 `PROMPT=$e]9;9;$P$e\<原 PROMPT>`；PowerShell 用 `-NoExit -EncodedCommand` 包一層 `prompt` 函式送 OSC 9;9。前端解析後更新分頁 cwd，500 ms 防抖後整份存 session。
- scrollback：有輸出才標 dirty，4 秒後用 `@xterm/addon-serialize`（最後 1000 行、排除 alt buffer）存檔；關窗時 `onCloseRequested` 再 flush 一次。crash 最多掉約 4 秒。
- 重開：先把快照寫回 xterm，游標移到最後一行非空白之下再印「已還原」分隔線。還原的分頁要點開才啟動 shell（lazy spawn）。
- 還原時先過 `squeezeBlankRuns`（`src/sanitize.ts`）：連續 3 行以上的空行壓成 2 行。原因：Claude Code 這類全螢幕 TUI 會用大量空行把輸入框墊到視窗底部，快照把這些空行原樣存下，還原後被當成歷史輸出，夾在舊畫面與「已還原」分隔線之間變成一大片空白、把內容往上擠（2026-10-20 使用者回報）。一般終端輸出的空行不受影響。
- 單一實例（single-instance plugin）避免兩個 panex 互相覆寫 session；視窗大小位置由 window-state plugin 還原。
